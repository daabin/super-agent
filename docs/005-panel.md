# 005 面板

在 DeepSeek Harness Web 侧边栏打开 **Superagent** 来监督智能体。面板优先展示需要人来处理的工作，然后是系统健康和历史。本文档建立在 [000 哲学](000-philosophy.md) 到 [004 提示词](004-prompts.md) 之上。

## 三个问题

打开面板按此顺序回答三个问题：

1. 现在有什么需要我处理吗？
2. 系统是否健康、是否在做正确的事？
3. 一件工作的历史是什么，从触发经过评估到工单？

## 页签

页签遵循工作流：**Overview（概览）**、**Source（来源）**、**Trigger（触发）**、**Eval（评估）**、**Execution（执行）** 和 **Settings（设置）**。在仓库和账号设置成功之前，Overview 显示缺失什么并链接到相关设置。

| 页签 | 展示 |
| --- | --- |
| Overview | 需要行动的工单、系统问题、最近 24 小时的活动计数，以及执行器负载。每个区块链接到它的详情页 |
| Source | 来源状态、设置问题和非零计数。被过滤的触发和被丢弃的消息覆盖与 Overview 相同的 24 小时窗口 |
| Trigger | 按“已订阅”“评估中”“24 小时新触发”或“全部线程”过滤的线程。每个线程展示其触发（最新在前）、决定和订阅 |
| Eval | 决定及其理由和匹配规则 |
| Execution | 执行器状态、暂停处理，以及按“打开”“待启动”“工作中”“等待触发”或“已结束”过滤的工单。工单详情展示操作、授权、等待的输入、订阅和派工 |
| Settings | 来源、评估、执行、提示词和部署。每组包含它的保存历史 |

### 阅读单条记录

被丢弃的消息链接到它的工单，或当它没有工单时链接到它的线程。来源页解释它的会话是否消失，或来源是否停止监听它。

仍由执行器拥有的人类后续被标记为 **Delivered to Ticket（已投递给工单）**，没有评估。线程也显示交回理由和仅上下文的订阅。**Evaluate again（再次评估）** 可以把该后续发给评估，或重试一个没有有效判断的触发：被其来源过滤的、评估 unavailable 的、或既没有非停止决定也没有执行器确认的已投递消息。

工单详情展示起始触发、决定和理由、范围和策略版本。派工和次要细节折叠在即时操作下方。**Retry（重试）** 在输入投递失败、或工单在受阻或失败报告后等待人时可用。已结束工单展示诸如 **Pull request merged（拉取请求已合并）** 或 **Stopped by a person（被人停止）** 之类的结果。

## 设置组

- **Sources：** 每个来源一张卡片，带开关、字段和已核实的账号事实。GitHub 还提供新 Issue、拉取请求、评论和默认分支 CI 的全量接收开关。轮询和读取限制在 Advanced 下。
- **Eval：** 策略版本和规则，然后是 **On each Source（每个来源）** 和评估设置。每个来源页签包含它的允许名单、成员同步、准入表和机器人名单。同步在启动时和 **Sync now（立即同步）** 时运行。准入表区分接收范围、发送者成员关系，以及消息是否针对智能体。评估设置选择接单模式、超时和研判模型。
- **Execution：** worker 模型、并发、目录根、prepare 命令和阻止的命令。点击可用变量会把它插入 prepare 命令。
- **Prompts：** **Edit（编辑）** 更改团队部分、内置部分和技能。**Full prompt（完整提示词）** 展示组装后的文本，并与已保存文本或默认值比较。**History（历史）** 列出各版本。已编辑的内置部分标记为已更改，可以重置；模板列出它们所需的占位符。

  一个更改了被覆盖默认值的升级会把它标记为 **Default updated（默认内容已更新）**。面板在团队文本上方比较新旧默认值。如果旧默认值没有记录，它改为把团队文本与新默认值比较。选择 **Keep my text（保留我的文本）** 或 **Use the new default（使用新默认值）**。被移除部分的覆盖列在页签栏下方，并在下次保存时丢弃。
- **Deployment：** 带 **Check again（再次检查）** 的启动问题、状态目录和机器限制。已保存的限制无需重启即生效。DeepSeek Harness 插件管理器展示同一页。

## 搜索

头部搜索按文本、id、飞书消息 id 或已存储的链接（例如 GitHub 评论 URL）查找触发。原始消息中缺失的飞书链接，只有在宿主在当前进程生命周期内读取它之后才能被搜索到。

搜索也按诸如 `#12` 或 GitHub URL 之类的引用查找线程，按标题或匹配的线程查找工单。

## 原则

1. **聚焦重要事项。** 每个元素回答三个问题之一，否则被移除。数字只在它改变监督者行动时出现。
2. **精确定义。** 分类有可检查的定义、互斥且覆盖所有情形，正如工单阶段那样。标签说明一行在等谁、需要什么，而不是内部状态码。
3. **一个概念一处。** 来源状态属于 Source；线程和触发的状态属于 Trigger；决定属于 Eval；工单属于 Execution。设置按它们配置的概念分组。Overview 汇总这些页并链接到它们，而不是成为又一个详情视图。
4. **领域结构。** 面板使用领域术语。内部标识符只出现在折叠的详情里，凡能解析的名称都取代标识符。
5. **诚实状态。** 计数等于它所链接列表的长度，没有任何状态与另一事实矛盾。
6. **默认安静。** 健康状态不占额外空间。问题必须可行动；一次性的网络错误不够。需要人的行直接提供其操作。页面说明保持一句话，把更多细节放进（?）工具提示。破坏性操作需要确认。
7. **一致的控制。** 使用 DeepSeek Harness 设计令牌和控制行为。同样的信息在整个面板里应看起来一样。每个设置块有一条保存栏，仅当存在变更、保存运行中或保存失败时可见。
