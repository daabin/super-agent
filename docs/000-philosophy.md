# 000 哲学

dsh-superagent 既是一个框架，也是一种与智能体协作的方式。它的核心原则：

**尽可能少地占用人的注意力，尽可能多地创造价值。**

项目中的每个部分都以它所消耗的注意力来衡量。一条消息、一次通知、一个问题、一项设置、一个面板元素、一段文档，都会消耗某人的注意力；而每一处都必须带来超过其成本的回报，否则就会被移除。

## 对智能体的要求

- **只在被要求时，或在有书面规则允许时才行动。** 只有当请求直接针对智能体、并且来自团队允许的人时才有效：来自允许名单上的人，或者来自团队开放接收请求的会话中的任何人。没人要求的工作需要有团队书写的规则，并且以一种只记录智能体本会做什么的模式开始。
- **只在有人必须行动或能够使用某个结果时才说话。** 它确认一次请求，并说明自己将做什么。工作期间保持安静。当结果就绪、需要做决定、或无法完成时再写消息。消息要简短，并且发到发起请求的那个会话里。
- **一次只问一个具体的问题，** 以结构化形式提出，让问题能到达人，而不是埋在一份冗长的报告里。
- **按影响而非努力程度停止。** 局部改动一直做到可评审的结果。需要设计决定的改动，则以一个清晰的问题停止。
- **诚实报告。** 草稿要标注为未完成，失败要如实报告为失败，绝不为了逃避提问而绕过限制。

## 对设计的要求

- **概念要少。** 设计只包含它的领域概念，例如来源（Source），以及它们的具体实现，例如 GitHub 和飞书。一项业务需求要么成为其中某个概念的属性，要么成为智能体遵循的一段提示词。设计不会为它新增概念。
- **设置要少。** 当某个值几乎适用于所有团队时，就用默认值代替设置。团队用文字描述的行为是提示词文本，而不是设置。
- **面板只展示需要人来处理的内容。** 它把等待人来处理的事项列在最前面。健康状态不占用任何空间。
- **文档按顺序阅读。** 每个编号文档只建立在它之前的文档之上，这样读者永远不会遇到尚未介绍过的概念。

## 责任

智能体会以你团队每天都能看到的账号来评论、发起拉取请求和给人发消息。它发出的每一条消息都会消耗你同事的注意力，你要为此负责。智能体能做的事越多，它的运营者就越要对团队负责：

- **从小处开始。** 从一个简短的允许名单开始，主动工作只做记录。等智能体本会做的事看起来正确后，再放宽这两者。
- **调优以减少噪音。** 当智能体很吵时，把它的提示词改得更短、更严格，或者暂停它。不要为了解释噪音而增加更多消息。
- **不要用它来制造数量。** 批量拉取请求、广播消息和无效忙碌，给团队带来的成本大于回报。
- **为它说的话负责。** 阅读智能体以你的名义发布的内容，出错时在提示词里纠正它。

目标是在正确的时间提供正确的帮助，而在其他任何时间都不打扰。
